# 2026-10-24 管理员入口与登录链接修复

## 结果与原因

生产修复已完成。用户在原已登录页面刷新后确认：“Admin 入口已恢复，后台可以打开”。

故障不是账号角色丢失。只读核对确认原账号仍为 `super_admin`，生产有 1 个 Super Admin 和 5 个 Full Admin，四项新迁移均未安装。新前端调用 `get_admin_access`、`has_admin_module`，生产返回 `PGRST202`；前端把异常转换为无权限，Navbar 因而隐藏 Admin。仅本地新数据库验收未覆盖“新前端＋旧数据库”，是此前发布验证的遗漏。

另外，两个正式域名都可访问，但登录回跳白名单缺少它们。默认 Site URL 为 www 地址，Google 登录使用当前 origin；从主域名发起的回跳可能回落到默认地址。注册代码也固定跳 www，且误把 127.0.0.1 开发环境当生产。这些路径已一并处理。

## 已完成、待用户统一发布的前端修复

- `loadAdminAccess`、`hasAdminModule` 共用兼容检查。仅 `PGRST202` 且消息准确指向相应新 RPC 时，才查询旧服务器的 `is_super_admin`、`has_role(admin)`；使用当前登录账号 ID，不信任邮箱、Profile role 或浏览器自报权限。

- AuthContext 保留账号切换与晚到响应保护，增加权限错误与安全重试。后台显示错误而不是误跳首页，导航提供重试入口。

- 旧数据库兼容模式下暂时禁用新邀请、角色变更及删除操作，明确提示需要安装更新。
- 注册确认邮件保持当前站点 origin，与 Google 登录的回跳策略一致。
