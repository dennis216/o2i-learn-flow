# 2026-11-02 至 11-08 上线推进计划

目标：尽快让真实学生完整使用已有课程与练习，并提供可兑现的宣传入口。前三个 Unit 视频由 partner 制作完成，本站任务是录入、发布和验收；宣传由 partner 负责。不以模块数量或未经验证的自适应效果证明成果。

工时为单人有效工作时间估计，不含素材制作、外部支付开户和学生反馈等待。

| 优先级 | 任务 | 难度 | 工时估计 | 完成标准 |
|---|---|---|---|---|
| P0 | 发布 Unit 1–3 视频课件 | 中，录入工作量较大 | 6–12h，取决于课节数和链接准备 | 标题/顺序/CB 映射正确，普通学生可播放，手机可用 |
| P0 | 同步对应小游戏 | 中 | 4–8h，素材可直接使用时 | 关联正确课节、发布、主要按钮可达；未完成的游戏不阻塞已有视频发布 |
| P0 | Contact page | 低 | 1–2h，联系方式及文案已确定时 | 有真实可用联系方式/反馈渠道，访客可达；不必先建复杂工单系统 |
| P0 | 阻塞使用的 UI 调整与真实路径验收 | 低至中 | 3–5h | 仅修裁切、遮挡、按钮不可达、导航/手机问题；课程→练习→解析→错题路径通过 |
| P1 | Solution Requests 最小闭环 | 中至高 | 8–16h，需先核对既有实现 | 学生提问并查看状态，授权管理员答复，学生看到答复；明确公开/私密与响应责任人 |
| P1 | 完善已有错题本 | 低至中 | 2–4h，仅体验补全范围 | 复用现有 Review；核对筛选、原题解析、刷新及隔离。全量分页/重新练习另估，不重建 |
| P2 | 题库自适应判定规则调整 | 中至高 | 3–6h，小幅规则修改范围 | 先检查实际选题摘要、题池及计时，再明确调整原因；保留边界与历史兼容验证 |
| P2，收费首发时升 P0 | 付款页面设计 | 中 | 2–4h，仅设计 | 明确收费对象、价格、购买后权益和支付后路径；支付接入/回调/权限/退款另估，不以设计当收款上线 |
| P3 | 游戏自适应 | 高，若指玩法难度调整 | 另行定义 | 本周不排；若指窗口裁切，应归入 P0 UI 修复 |

## 推进顺序

1. 前半周：真实视频发布、可用游戏同步、Contact 和阻塞 UI；Unit 1 可先发布，不等待全部三个单元齐套。
2. 中段：学生完整路径验收，partner 可以据实际开放范围宣传；记录真实反馈，不制造学生使用数据。
3. 后半周：Solution Requests 最小闭环或错题本补全，按剩余时间择重点；不能承诺九项全部完成。
4. 自适应规则和付款设计仅在主线不受阻时推进；收费首发则先完成付款与权益交付闭环。

对外或申请材料展示：保留真实课程目录、可访问入口、使用说明、版本记录，以及经允许的真实反馈。不保证任何评审者访问网站，避免把未上线功能写成可用成果。

当前基础：Review 已有最近十条错题及原题解析；不是从零开发。当前计划不是生产状态证明，执行前核对部署和真实素材清单。
