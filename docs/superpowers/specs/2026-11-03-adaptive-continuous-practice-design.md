# 自适应练习重设计：无限练习 + 复盘（第一版设计）

状态：设计稿，待审。尚未修改代码或部署。
日期：2026-11-03

## 1. 为什么做

O2I 想把自适应做成产品核心：帮学生自学，也给老师可靠、可行动的信息；靠逐步积累规则、题目和作答数据形成优势，而不是堆功能。

现在的自适应（生产中的 adaptation-v2）一次挑好 5 题，存在这些问题：

1. 同一道题重做做对，之前的错误就被"洗掉"（只看每题最新一次结果）。
2. 题少时猜对一两题就会升难度。
3. 题库太少，规则经常找不到合适的题，只能随便补。
4. 难度是出题人凭感觉标的，没有用数据核对。
5. 用时由浏览器上报，可被修改，慢也不等于不会。
6. 学会的内容不会再回头检查。
7. "补错"要求同技能、同呈现形式，条件太严，经常落空。
8. 选项上的误概念标签存在但没用。
9. 没有老师视图。

本设计用"一题一题出"的无限练习解决 1、2、3、6、7，并为 4、8、9 积累数据。

## 2. 目标、非目标、反目标

**目标**

- 学生能在一个 Topic 或所有 Topic 里一直练，直到自己点 End session，然后看复盘。
- 每做完一题，下一题马上按表现调整。
- 每道题为什么出现都由服务器记录，以后能用历史数据检验和改进规则。

**非目标（第一版不做）**

- 误概念诊断、掌握度百分比、复杂模型（Elo/BKT 等）。
- 用作答数据重新给题目定难度。
- 老师端页面（目前系统里没有班级/老师-学生关系）。
- 游戏内作答接入。

**反目标（做了就算失败）**

- 把简单正确率包装成"掌握度"或"误概念诊断"给学生或老师看。
- 为了"无限"偷偷循环旧题，让学生以为是新推荐。
- 学生改浏览器数据就能改变选题或状态。
- 破坏现有 5 题模式、Review、课程练习和历史数据。

## 3. 方案比较（已选 A）

| 方案 | 做法 | 取舍 |
|---|---|---|
| **A. 服务器一题一题出（选定）** | 每答完一题，请服务器按规则挑下一题并记录原因 | 能完整实现规则；记录可信、可复算。需要改数据库（现在一次最多 5 题），每题之间多一次请求 |
| B. 浏览器先拿一批题自己挑 | 规则写在前端 | 最快，但学生可改、服务器记录不完整；仓库里的 `src/lib/adaptivePractice.ts` 原型就是这种，从未接入。不采用 |
| C. 5 题做完自动接下一组 | 几乎不动数据库 | 做错后不能马上变简单，做不到已定规则。不采用 |

选 A 的原因：唯一能完整实现已定规则，并且延续现有"服务器判分、服务器选题、记录冻结"的做法。

## 4. 页面（用户已确认）

练习页顶部三个按钮：

```
[ Start 5 questions ]  [ Free practice ]  [ Review ]
        现有                  新加            现有
```

| 入口 | 范围 | 题量 | 结束 |
|---|---|---|---|
| Start 5 questions | 所有 Topic | 5 题 | 做完自动结束 |
| Free practice（新） | 所有已发布 Topic | 不限 | End session → 复盘 |
| Topic 卡片（改，原为 5 题） | 该 Topic | 不限 | End session → 复盘 |
| Review | 以前做错的题 | — | 不变 |
| 课程课节 "Practice this Topic"（改，原为 5 题） | 该 Topic（保留课程 AB/BC 范围） | 不限 | End session → 复盘（用户已确认） |

- 练习中 End session 按钮始终可见。
- 关掉页面没点 End：作答都已保存；下次进练习页提示"你有一次没结束的练习：继续 / 结束并查看复盘"。
- 已出题但没作答就结束：记为"未作答"，不算错。

## 5. 判断规则（第一版）

### 5.1 用什么当证据（用户已确认）

- **判断会不会，只看学生第一次做某道题的结果。**重做同一题只算复习。
- 用时只用于提示（"这题可以再熟练一点"），不影响难度、状态和选题。
- 选项切换轨迹照常保存，第一版不参与判断。

### 5.2 Topic 状态（三档文字，不显示百分比）

按学生在该 Topic 最近 6 道"第一次作答"的题计算（我的提议，数字待真实数据校准）：

| 状态 | 条件 |
|---|---|
| 题太少还看不出 | 少于 4 道 |
| 需要再练 | ≥4 道，且第一次做对的比例 < 75% |
| 目前比较稳 | ≥4 道，且第一次做对的比例 ≥ 75% |

另外：复习题（见 5.3）做错，该 Topic 直接回到"需要再练"。

每个状态附一句原因，例如"最近 4 道新题对了 1 道"。

### 5.3 每做完一题，下一题怎么挑

**Topic 卡片模式**

1. 第一题：中等难度的新题。（我的提议：该 Topic 状态是"需要再练"时从简单题开始。）
2. 做错 → 下一题仍在本 Topic，换一道更简单的新题（用户已确认）。
3. 没有更简单的新题 → 直接出一道同难度新题，**不提示学生**（用户已确认）。
4. 连续做对 3 道新题 → 升一档难度。
5. 同一 Topic 连续错 4 题 → 提示去看本节视频或解析（用户已确认）；学生可选择继续，计数清零。
6. 每做约 5 题，插一道"之前第一次就做对、且距今 ≥3 天"的本 Topic 题作复习；没有就跳过。
7. 本 Topic 新题全部做完 → 只显示两个选择："看这节视频 / 解析"和"换个 Topic 继续"。**不重出旧题，不提供重做错题**（用户已确认；错题重做只在 Review）。

**Free practice**

先选 Topic，再按上面规则挑题：

- Topic 顺序：需要再练 → 题太少还看不出 → 目前比较稳（只在约每 5 题一次的复习位出现）。
- 我的提议：在同一个 Topic 连续出最多 5 题再重新选 Topic，避免每题跳来跳去；该 Topic 新题用完就换下一个。
- 连续做错时留在同一 Topic 换简单题（用户已确认）。
- 所有 Topic 新题都做完：提示并让学生结束复盘或去 Review。

**Start 5 questions**

第一版保持现有 v2 选题规则不变，降低上线风险；第 2 阶段再改为同一套状态和 Topic 顺序（一次挑 5 题，不能逐题调整）。

**安全上限**：单次练习最多 100 题。

### 5.4 推荐原因

每题由服务器生成一句原因并保存，例如：

- "上一题错了，换一道更基础的同类题"
- "连续做对 3 道，提高一点难度"
- "隔了几天，检查一下 2.1 有没有忘"
- "这是你还没怎么练过的 Topic"

## 6. 复盘页（用户已确认）

1. **这次做了什么**：做了几题、其中几道新题、新题第一次做对几道；大概用时（标注仅供参考）。
2. **按 Topic**：三档状态 + 一句原因。不显示掌握度数字。
3. **这次做错的题**：可逐题看解析；自动进入 Review。
4. **下一步建议**：一句话 + 按钮（如"建议继续练 2.3 → 开始"）。

## 7. 数据改动（给实现者）

- `question_practice_sessions`：增加模式（`set5` / `continuous`）、结束时间。
- `question_practice_items`：位置上限从 5 放宽到 100；增加服务器发题时间（可用来核对浏览器上报的用时上限）和本题入选原因（含规则版本，如 `continuous-v1`）。
- 新 RPC：开始/继续无限练习、取下一题（有未作答题时返回它，保证刷新和重复请求不会多发题）、结束并返回复盘数据。
- 作答继续走现有 `submit_question_practice_v2`。
- 状态计算写成一个服务器端函数，5 题模式、无限练习和复盘共用。
- 旧 session、旧 `selection_summary` 保持原样可读。
- 按仓库惯例做生产包：`docs/question-bank/production/<名称>/` 下的 preflight / deploy / verify / README_ZH / VALIDATION，并通过隔离数据库 + 浏览器验收。

## 8. 路线

| 阶段 | 内容 | 前提 |
|---|---|---|
| **1（本设计）** | 无限练习、复盘、"只看第一次作答"、三档状态、推荐原因记录 | 无 |
| 并行（内容） | 每个已发布 Topic 至少每种难度 3 道题 | 这是规则能起作用的最大瓶颈 |
| 2 | 5 题模式完全对齐；调整阈值；用错误选项上的误概念标签做"可能的误解"提示（同一标签在不同题上重复出现才提示） | 有真实作答；误概念标签经审核 |
| 3 | 老师端：每个学生、每个 Topic 做了几道新题、第一次做对比例、最多人选的错误选项；样本少明确标出 | 先建班级/老师-学生关系和授权 |
| 4 | 游戏作答接入：游戏把每道题映射到规范题目版本或 Topic/Skill，作为单独的"游戏活动"记录；不同游戏的分数和用时不互相比较，也不直接算进"会不会"的判断，除非题目对应到服务器判分的规范题 | 游戏能上报事件 |
| 5 | 用数据给题目定难度（每题有足够多学生作答后） | 每题约 30 个以上不同学生的第一次作答 |

## 9. 怎么验证效果

上线后从服务器记录里直接统计（不需要额外埋点）：

- **规则有没有落空**：多少题是"想出简单题但没有、改出同难度"的；多少次练习因新题用完而停止。→ 告诉我们哪里缺题。
- **重复率**：无限练习中重出旧题的比例（复习题以外应为 0）。
- **连错 4 题提示后**：学生是看视频、继续做还是结束；继续做的下一道新题对不对。
- **"需要再练"之后是否变好**：同一 Topic 后续新题的第一次做对比例是否上升。
- **复习题**：隔几天后的复习题对的比例，用来判断"比较稳"是否可信。
- **复盘**：多少次练习点了 End 看到复盘；复盘里"下一步"按钮被点的比例。

数据少的阶段以逐条看记录、找学生访谈为主，不急着下结论；阈值调整都升规则版本号，便于新旧对比。
