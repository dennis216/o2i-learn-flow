# 随机取题与 Topic 内自适应上线

所有 SQL 只在明确授权后由操作者执行。不要重跑历史迁移或全部 migrations。

## 前置：真实题学生闭环

1. 先完成 Team/Admin 兼容修复，核对学生练习基础迁移 `20261021000000` 的实际账本和只读验收结果；缺失才执行原学生练习上线包。
2. 普通学生账号对管理员已审核发布的真实题作答：提交前无答案、提交后判分与解析、刷新保留、另一账号不可读取。
3. 本轮本地测试不能代替以上生产验收；不能自动发布真实题或将合成题传入生产。

## 随机抽题

依次执行完整 `10_random_deploy.sql`、`11_random_verify.sql`，要求 all_checks_pass=true。

- 每组最多 5 题，同组唯一；未发过的题优先，其余按最早发题时间补齐，同条件随机。
- 判断重复用 question_id，发布新版本不会重置发题历史。
- 同账号创建会话串行化；已存在的会话只回读，不换题或版本。选项顺序不变。
- 数据库替换原 RPC，旧前端兼容；新建会话生效，历史会话不变。
- 数据库成功后再部署前端。失败先核对具体报错与账本，不手工补写账本或重新运行旧包。

## 本地复验

使用 `scripts/student-practice.test.mjs` 的隔离 PostgreSQL/Auth/REST/浏览器测试，需 Docker、已有 Playwright 与 Chrome。`O2I_PLAYWRIGHT_MODULE` 可指向已安装的模块，不新增项目依赖。

部署包由 `node scripts/generate-practice-selection-deploy.mjs` 生成，原始迁移是唯一来源。每份部署事务核对前置迁移指纹，拒绝重复执行，写入对应原文账本。

## Topic 内自适应

随机迁移完成后，依次执行完整 `20_adaptive_deploy.sql`、`21_adaptive_verify.sql`，要求 all_checks_pass=true。原学生练习 11 项目录/权限检查也应仍通过。两份新迁移分开执行；不包含 Team schema 迁移。

- 同账号、同 Topic 最近 10 道不同题，每题只取最新作答，按作答所绑定版本的 Topic 归类。
- 少于 5 题：medium。否则正确率 <50%：easy；50%–<80%：medium；>=80%：hard。只用服务端对错，不使用设备用时、旧浏览器成绩或 AI 推断。
- 排序：未发题优先 → 与目标难度距离较近 → 等距优先较低难度 → 最早发过 → 同条件随机。先保证新题，不为追求目标难度重复已做题。
- 全库入口只随机去重复，target_difficulty=null；不跨 Topic 推荐。
- selection_summary 保存 rule_version、target_difficulty、sample_count、correct_count、fallback_count。仅新会话生成；旧会话 NULL。当前摘要不是掌握度，不预测考试分数。
- 新前端兼容无摘要的旧响应，旧前端忽略新字段。升级 SQL 成功再部署前端。
- 有问题时保留历史作答与会话，前端可恢复上一版；不要通过删表/删列回滚。抽题规则修复使用新的前向迁移。

## 试点验收

选一个 Topic，准备至少 15 道人工审核通过的题（easy/medium/hard 各至少 5 道）。这只是验证抽题与回退的最低试点池，不是教学有效性证明。旧 8 题继续保留，不伪造题目或为凑数量更改难度。

上线后记录：commit、迁移目录与账本检查结果、实际发布题数、普通账号浏览器验收。至少检查第一组/下一组/刷新、正确与错误提交、摘要解释、另一账号隔离。监测 RPC 错误与真实空题池；不采集答案内容到额外日志。
